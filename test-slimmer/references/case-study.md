# 案例：表格组件测试精简

本案例来自一次 Vue 表格组件测试维护，已去除内部项目名称、仓库地址、业务源码和本机路径。数字是该次工作的记录，不是其他项目的目标或预期收益。

## 请求与边界

先分析测试冗余，再在独立分支实施精简。用户希望保留原测试点，也允许在维护收益明显时少量删除低价值检查；之后另行授权独立审查、修复、提交、推送和创建 MR。

没有改动组件实现，也没有把测试精简扩展成测试框架迁移。

## 如何找到主要收益

重复主要集中在四处：组件挂载配置、布局与鼠标事件 mock、浏览器初始化/拖拽动作，以及完整 DOM 快照。若干浏览器用例重复覆盖相同场景，另有 61 处调用仅生成成功截图，不做图片比较。

底层算法和边界单测已经较短，保留。主题、密度、RTL、真实滚动条、受控更新、错误回调和基础组件隔离等有区分度的覆盖也保留。

| 操作 | 收益 | 覆盖如何保留 |
| --- | --- | --- |
| 统一挂载与布局 mock | 去掉重复默认配置和事件构造 | 场景数据、特殊挂载选项和预期值仍由各用例声明 |
| 参数化数值编辑入口、主题与对齐场景 | 同一逻辑只写一次 | 不同 API 入口和配置组合仍分别执行 |
| 合并固定列与筛选项的重复浏览器用例 | 减少两个完整场景 | 独有断言迁入保留用例，覆盖左右固定列及两种主题 |
| 摘要化 demo 快照 | 去掉大量 SVG、包装节点和样式展开 | 保留表头、行内容、控件状态，审查后补入合并跨度 |
| 成功截图改为失败截图 | 删除重复取证代码 | 保留全部 4 处图片基线断言 |

共享 helper 只抽出稳定步骤。拖拽中的边界条件、不同尺寸和显式预期值没有由 helper 根据组件输出“计算答案”。

## 三个值得复用的教训

### 删除语句时检查控制流

中间版本删除了一个条件截图，却残留 `if (dark)`，把紧接着的表头全选操作变成只在暗色下执行。完整回归中的三个主题用例因此失败。

修复是删除残留条件，恢复无条件全选；三个用例定向复测通过。这是一次具体的重构回归，有明确原因与修复，不能描述为“重跑就好了”。

### 操作 API 已失效不等于覆盖无用

密度 demo 原测试直接点击页面中的密度文字，但 UI 已改成 Row Height 菜单。原基线同样超时。更新为打开菜单、选择选项再关闭菜单，保留原有尺寸、主题、编辑和固定区域检查。

另一个冷启动失败通过等待目标 demo 可见解决。没有增加固定睡眠来掩盖加载问题。

### 文本一样，结构语义仍可能错误

独立审查发现：摘要只记录文本和控件状态，遗漏了 `rowspan/colspan`。例如首行 `rowspan=3` 误变成 `1`，后两行仍隐藏对应单元格，文本和单元格数量都可能保持不变；分组表头的错误跨度同样会漏报。

原全量快照覆盖这些属性，其他用例没有等价断言。这属于核心语义，用少量代码补入非默认跨度即可：

```text
Alpha [rowspan:3] | 1,000.00 | [checkbox:off]
Group [colspan:3] | Status [rowspan:2]
```

补回后仅更新目标 demo 的三个快照条目，26 条 demo 用例在不更新快照的 CI 模式下通过；普通组件快照逐块保持不变。定向独立复审通过。

这个发现说明：快照压缩应保留原测试的可观察契约，不能只保留文字。

## 怎样处理原本就红的测试

改动前已保存测试基线。改动后仍有 5 个浏览器失败：3 处图片基线、一个弹层定位断言和一个暗色编辑背景断言。

因为组件实现没有变化，使用原基线的测试在相同环境作对照，5 项均复现；3 张实际图片逐字相同。另有 30 个不相关 demo 快照失败，名称集合与改动前一致。

这些证据支持“没有发现本次引入的对应渲染差异”，不支持“旧断言应该被删除”或“所有测试通过”。没有重录图片、放宽阈值或更新不相关快照。

最终浏览器结果来自一次完整执行加修复后的定向复测，累计 127/132 通过。交付中明确说明这个统计方式和剩余失败。

## 最终结果

| 指标 | 精简前 | 精简后 | 变化 |
| --- | ---: | ---: | ---: |
| 本次涉及的测试源码及配置行数 | 9,365 | 8,350 | −1,015 |
| 目标组件 demo 快照行数 | 5,134 | 469 | −4,665 |
| 组件及底层单测数量 | 189 | 189 | 0 |
| 浏览器用例数量 | 134 | 132 | −2 |

22 个文件净减少 **5,680 行**，已计入两个新增 helper。代码和快照统计分别计算；没有把累计删除行数当作净收益。

最终 189 条单测和 26 条目标 demo 测试通过，格式与静态检查通过；浏览器累计 127 条通过，5 项已证实的基线失败保留并记录。独立审查的唯一有效发现已修复，之后才按用户授权提交、推送和创建 MR。

可迁移的方法是：先建立可比较基线，再按测试点迁移覆盖；优先精简重复准备与低信号快照；用实际执行和独立审查检查损失，最后报告真实净收益和验证边界。
